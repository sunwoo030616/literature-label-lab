# V4: RAG 문헌 저장소 — 첫 검증 결과

기존 분류 실험과 분리된 SQLite/FTS5 검색 저장소다. 기존 모델 평가 점수는 변경하지 않는다.

## 실행한 실험

- 공식 LitCovid CSV 3개에서 33,699행을 스트리밍 처리했다.
- PMID와 정규화한 제목·초록 SHA-256으로 중복 43행을 제외했다.
- 초록이 없는 11행은 별도 quarantine 테이블에 기록했다.
- 고유 문헌 33,645건을 적재하고 BM25 제목 가중치 3, 초록 가중치 1 검색을 구현했다.
- 동일 파일을 다시 적재했을 때 추가 문헌은 **0건**이었다.
- 500행마다 커밋하므로 중단 후 처음부터 재실행하면 완료한 문헌을 건너뛴다. 행 위치 체크포인트 방식은 아니다.
- 입력 누락·중복·재실행·검색·쿼리 문자열·검색 개수 제한을 검증하는 단위 테스트 2개가 통과했다.
- 실제 실행 수치, 원본 파일 해시, PMID 조회 쿼리 계획은 `../results/ingestion.json`에 보존했다.

## 실행

저장소 루트에서 Python 표준 라이브러리만 사용한다. SQLite에 FTS5가 필요하다.

```sh
python3 -m unittest discover -s extension_v4/tests -v
python3 extension_v4/src/corpus.py --db extension_v4/data/corpus.sqlite3 --source data/raw/train.csv data/raw/dev.csv data/raw/test.csv --report extension_v4/results/ingestion.json
```

결과 파일은 새 DB에서 최초 적재와 재실행을 순차 측정한 기록이다. 이미 적재된 DB에서 실행하면 최초 적재 수치는 달라진다. 원본 CSV와 생성 DB는 Git에 포함하지 않는다.

## 설명할 때의 범위

“33,645개 문헌의 제목·초록을 중복 제거하여 저장하고, 재실행해도 중복이 생기지 않는 배치 적재와 BM25 검색을 구현했다”라고 설명할 수 있다. 백만 건 처리, 실시간 외부 수집, 논문 전문 검색, RAG 답변 품질 향상까지 검증한 것은 아니다.

현재 문헌은 최초 적재본을 유지한다. 같은 PMID의 수정본은 덮어쓰지 않으며 DOI는 검색 인덱스만 있고 고유 키가 아니다. 수정본 이력과 충돌 분류는 후속 개선 대상이다. DB에는 기존 공식 train/dev/test 모두 들어 있으므로 **이 DB를 기존 분류 실험의 학습 데이터로 사용하면 안 된다**. 검색 평가는 별도 질의·문헌 관련성 기준으로 설계해야 한다.

## 다음 검증 순서

1. 검색 질의와 관련성 판정 기준을 먼저 고정하고 BM25·dense·hybrid 검색을 비교한다.
2. 프롬프트 버전과 근거 인용·답변 유보 규칙을 분리하고 무료 로컬 LLM의 실패를 기록한다.
3. MCP 도구 서버와 클라이언트 통신을 실제 실행하여 검색·문헌 조회를 검증한다.
4. 동일 검증을 반복할 수 있는 프로젝트 Skill과 포트폴리오 해설을 만든다.

이 문서의 다음 순서는 미구현 계획이며 완료한 기능과 구분한다.
