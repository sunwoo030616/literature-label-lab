# 추가 개발을 쉽게 설명하기

입력은 공개 문헌의 **제목·초록**입니다. 논문 PDF의 본문·그림·표 전체를 읽는 시스템을 구현한 것은 아닙니다.

## 왜 문헌을 조각으로 나누나요?

처음 모델은 제목과 초록의 앞부분을 하나의 벡터로 만들었습니다. 긴 문헌에는 앞부분과 뒷부분에 서로 다른 주제가 나타날 수 있습니다. 문헌을 최대4개의 token window로 나누면 여러 부분을 각각 표현할 수 있습니다. 단, 4개를 넘으면 균등 간격으로 일부만 고르므로 원문 전체를 항상 읽는 것은 아닙니다.

## Bag이란?

조각 여러 개를 한 문헌으로 묶은 것입니다. 조각 하나하나에 정답 주제가 있는 것은 아니고, 문헌 전체에 여러 주제 라벨이 있습니다. 이런 구성이 기존 개별연구에서 공부한 multi-instance multi-label 문제와 연결됩니다. T-MDML 전체 모델을 구현했다는 뜻은 아닙니다.

## 단순 평균과 attention은 어떻게 다른가요?

평균은 모든 조각을 비슷한 비중으로 합칩니다. 주제별 attention은 '진단'과 '치료'를 판단할 때 서로 다른 조각에 비중을 줄 수 있도록 학습합니다. attention weight를 보면 어느 조각을 주로 사용했는지 살펴볼 수 있지만, 그 조각이 정답의 증거나 모델 판단의 인과적 설명이라고 보장하지는 않습니다.

## 관계를 학습에 넣는다는 것은?

V1/V2의 단순 관계 실험은 모델이 낸 점수를 나중에 바꿨습니다. 이번에는 서로 관련 있는 주제의 분류기 가중치가 너무 다르지 않도록 학습 loss에 제약을 넣습니다. 관계를 잘못 추정하면 서로 다른 주제를 구분하기 어려워질 수도 있으므로, 관계 없음·실제 관계·무작위 관계를 비교합니다.

## 512 LoRA 미세조정은?

같은 encoder의 모든층 LoRA 미세조정에서 읽는 길이를256→512로 늘립니다. 더 많은 문장을 볼 수 있지만 계산량도 늘어납니다. 점수만이 아니라 학습시간·추론비용까지 보고, 동일한 seed17/epoch 선택 규칙으로 비교합니다. 단일 추가 학습의 결과이며 완전한 통계적 검증은 아닙니다.

## 확률 보정과 정확도 개선은 다른가요?

모델 점수가 .9라고 해서90% 맞는 것은 아닙니다. temperature scaling은 별도의 calibration 문헌에서 점수의 과신/저신뢰를 조절합니다. 분류 임계값도 같은 함수로 변환하면 맞힌 라벨은 그대로입니다. 이 상태에서 NLL/Brier/ECE가 좋아지는지 확인하는 것입니다. F1이 그대로인 것은 실패가 아니라, 확률 품질과 분류 정확도가 다른 성질이라는 뜻입니다. 물론 확률 품질도 실제 평가에서 나빠질 수 있습니다.

## 백엔드에서 더한 것은?

문헌 내용 해시와 모델 버전을 저장해 동일 입력의 중복 등록을 막고, AI 예측과 사람이 검토한 결과를 분리합니다. 검토할 때 revision이 오래됐으면409로 거절해 다른 검토 내용을 덮어쓰지 않게 합니다. DB를 다시 열어도 결과가 남는지 확인합니다. 근거 문장이 원문에 없는 경우 저장하지 않지만, 원문에 있다는 사실만으로 주제가 옳다는 판정을 자동으로 내리지는 않습니다.

## 기존 연구와 어떻게 연결해서 말하나요?

“개별연구에서 배운 bag·라벨 관계 개념을 문헌 처리에 적용했습니다. 단순한 분류 성능만 비교하지 않고, 과적합 원인을 진단하고 무료 encoder 미세조정·문헌 bag attention·관계 규제를 실험했습니다. 생성형 LLM의 인용 검증과 사람 검토 workflow도 구현해, 모델 결과를 서비스에서 어떻게 다룰지까지 검증했습니다.”

최종 수치는 REPORT 문서와 실제 raw 결과로 확인하고, 개선되지 않은 조건·기존 테스트 재사용·감사 표본의 한계를 함께 설명합니다. 기존 연구 기간과 이번 개발 기간을 구분합니다.

## 최종 새 내부 확인은 무엇인가요?

V1의 test와 V2에서 처음 분리한 audit는 개발 과정에서 반복해 보게 됩니다. 그래서 예정된 모델과 프롬프트·threshold를 모두 고정한 다음, 이전 분할에 쓰지 않은 문헌1,000편을 한 번 더 확인합니다. 이 결과로 다시 모델을 고르지 않습니다. 그래도 같은 원천 LitCovid에서 뽑았으므로 '다른 연구 분야에서도 검증됐다'고 말하지 않습니다.

## attention이 설명이라는 것을 어떻게 확인했나요?

색이 진한 문단이 있다고 해서 그 부분이 판단의 원인이라고 말할 수는 없습니다. 고정 모델에서 가장 높은 비중·가장 낮은 비중·무작위 문단을 하나씩 가리고 예측의 변화를 비교합니다. 예측이 바뀌었다는 사실은 해당 입력에 민감하다는 뜻입니다. 문단을 지우면 문맥과 나머지 문단의 비중도 함께 달라지므로, 사람이 납득하는 정답 근거나 인과성을 증명한 것은 아닙니다.

## 미세조정한 모델을 배포할 때도 작은가요?

학습한 LoRA와 분류 head만 따로 저장하면 약30만 개 값만 필요합니다. 하지만 원본 BiomedBERT는 별도로 필요합니다. 따라서 “모델 전체가1MB”라고 쓰면 틀립니다. 저장용 adapter를 작게 전달하는 것과 전체 추론 메모리를 줄이는 것은 구분합니다. 추론 시에는 작은 행렬의 곱을 원본 행렬에 합칠 수 있어, 같은 문헌에서 확률과 라벨이 유지되는지 실제로 검사합니다.

## “LLM보다 BiomedBERT가 좋다”고 결론 내리면 되나요?

이번40편에서 특정 분류기 결과가 높았다고 모델 계열 전체의 우열로 일반화하면 안 됩니다. 분류기는 과제 라벨4,000편으로 학습했고 최대256 BERT token을 봅니다. Qwen은 zero/few-shot으로 최대1,600 Qwen token의 현재 문헌과 프롬프트를 봅니다. 같은 문헌에 대한 두 pipeline의 결과 비교이지 학습·입력·계산 예산을 같게 맞춘 아키텍처 실험은 아닙니다. Qwen의 zero/few-shot끼리는 모델·현재 문헌 예산·출력 규칙을 맞추고 train 예시를 추가한 효과를 탐색합니다.

## 왜 TF-IDF도 다시 튜닝하나요?

핵심은 BERT의 점수 하나를 올리는 것이 아니라, 같은 과제에서 어떤 선택이 실제로 나은지 확인하는 것입니다. 문헌 표현의 크기와 분포가 다르면 같은 C값도 같은 효과를 내지 않습니다. 그래서 BERT 분류기의 규제를 고른 뒤, TF-IDF도 검증 데이터에서 같은 후보 수로 규제를 선택했습니다. 최종 표에서는 최초 기본값과 새로 튜닝한 단순 모델을 모두 남깁니다. 미세조정이 단순 모델보다 무조건 낫다는 결론을 먼저 정하지 않습니다.

## 임계값 안정화는 무엇을 해봤나요?

“점수가 어느 값 이상이면 그 주제로 볼까?”의 경계가 임계값입니다.512 모델은 일부 주제를 더 많이 잡으면서 오탐도 늘었습니다. 그래서 기존 경계를 보존하고, 라벨별 경계와 공통 경계를 섞는 비중을 tune600 내부5fold에서만 골랐습니다.256은 기존 라벨별 경계가,512는 공통 경계가 선택됐습니다.512의 기존 테스트는 더 낮아지고 기존 감사는 조금 높아져 일관된 이득은 확인하지 못했습니다. 이는 실패도 포함한 후속 대조이며, 새로운 최종 표본의 결과를 보고 다시 경계를 바꾸지 않습니다. 확률값을 보정하는 temperature scaling과 다른 실험입니다.
