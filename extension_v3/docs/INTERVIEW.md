# 면접에서 설명할 질문과 답

## 이 프로젝트를 한 문장으로 설명하면?

“논문에서 공부한 복수 라벨과 문헌 bag 개념을 구현해 보고, 처음 낮게 나온 BiomedBERT 결과의 원인을 찾아 무료 미세조정·근거 검토 workflow까지 확장한 실험입니다.”

## AI, BiomedBERT, Qwen은 각각 무엇인가요?

AI는 넓은 범주입니다. BiomedBERT는 생의학 텍스트를 숫자 표현으로 바꾸는 encoder이고, 그 위에 붙인 분류기가 여러 주제를 선택합니다. Qwen은 다음 단어를 생성하는 decoder 언어모델로, 주제와 원문 인용문을 JSON으로 출력하게 했습니다. 둘은 같은 데이터에서 역할이 다르며, “AI를 하나 더 붙였다”는 이유로 성능 향상을 가정하지 않았습니다.

## 처음에는 BiomedBERT를 학습하지 않았나요?

원본 언어모델 가중치는 고정하고 문헌 표현 위에 분류기만 학습했습니다. 이번 후속 실험은 마지막2개 층의 원본 가중치 또는 모든층의 추가 LoRA 행렬을 실제 task loss로 업데이트했습니다. 사전학습부터 새로 한 것은 아닙니다.

## 왜 TF-IDF보다 낮았나요?

확인한 원인 중 하나는 분류기 과적합입니다. 같은 문헌 벡터에서도 C1은 학습 .981/검증 .776이었고, 규제가 강한 C.01은 학습 .869/검증 .813이었습니다. 같은 seed17 테스트에서 .7484→.7927로 개선됐습니다. “BERT 표현 자체가 나쁘다”는 결론은 이 설정 점검보다 앞서 내릴 수 없습니다.

## 긴 문헌을 잘라서 그런 것 아닌가요?

그 가능성도 별도로 시험했습니다. 512 평균 표현의 테스트 .7893은 튜닝한256의 .7927보다 높지 않았습니다. 512 CLS는 .7818이었습니다. 기존 감사에서는 pooling별 순위가 달라졌습니다. 입력 길이는 한 요인이지만 잘림 하나만으로 초기 저성능을 설명할 수 없었습니다.

## 마지막2개 층 미세조정이 가장 좋은 방법인가요?

기존 테스트에서는 .8460이 나왔지만, 그것만으로 우월한 구조라고 결론 내리지 않습니다. 마지막2개 층은3epoch, LoRA는1epoch이고 attention 구현과 dropout도 달랐습니다. 원본 가중치/adapter가 실제로 바뀌었는지 검사했고, 점수와 조건을 함께 보고합니다. 최종 새 감사 결과는 REPORT에서 별도로 확인합니다.

## LoRA의 장점과 한계는?

원본 encoder를 고정하고 작은 두 행렬 A/B를 추가해 업데이트할 수 있습니다. 이번 학습 대상은 head를 포함해300,295개입니다. 작은 adapter를 따로 배포할 수 있지만 약420MB의 원본 모델은 여전히 필요합니다. 다른 층을 학습하는 모델보다 언제나 정확하거나 빠르다는 뜻은 아닙니다.

## 원논문을 재현한 건가요?

아닙니다. T-MDML의 bag·라벨 관계 개념에서 출발했지만, 원논문의 triplet 목적함수와 전역/라벨별 거리 행렬을 구현한 것은 아닙니다. 이번 후속 모델은 frozen 문헌 chunk 위의 label attention과 classifier weight 관계 규제입니다. 개념을 이해한 뒤 별도 질문으로 확장한 실험입니다.

## 왜 무작위 관계와도 비교했나요?

관계를 넣어 점수가 조금 올라도 “라벨 의미를 잘 이용해서”라고 바로 결론 낼 수 없습니다. 비슷한 구조·규제 효과만으로도 달라질 수 있습니다. 라벨 대응을 섞은 관계도 같은 후보 선택 예산으로 비교했습니다. lambda0이 선택되면 관계 규제를 쓰지 않은 것으로 기록합니다.

## 인용문이 원문에 있으면 LLM 설명이 맞는 건가요?

아닙니다. 문자열 검사는 존재하지 않는 문장을 근거로 제시한 오류를 거릅니다. 그 문장이 해당 주제를 논리적으로 뒷받침하는지까지 판단하지는 않습니다. 원문 일치율과 주제 F1을 따로 보고, LLM 후보는 사람의 확정 라벨을 덮어쓰지 않게 했습니다.

## Qwen도 미세조정했나요?

Qwen은 무료4bit 로컬 모델의 가중치를 그대로 사용했습니다. zero-shot과 train-only 예시를 넣은 in-context 방식을 비교했습니다. 실제로 미세조정한 모델은 BiomedBERT의 일부/LoRA입니다.

## 검증 데이터·테스트·감사의 차이는?

train4,000편은 가중치를 학습합니다. tune600편은 설정·epoch·threshold를 고르고, calibration400편은 확률 보정에 사용합니다. 기존 test2,488편과 V2 audit1,000편은 개발 중 반복 확인했다는 사실을 공개합니다. 모든 모델을 고정한 뒤 분리한 최종 내부1,000편으로 한 번 더 확인하되, 같은 출처 데이터이므로 외부 검증이라고 부르지 않습니다.

## 제가 직접 확인할 최소 실행은?

1. REPORT의 동일 분할 표에서 최초 frozen / 튜닝 frozen / partial / LoRA 결과를 찾아 차이를 설명합니다.
2. 선택한 모델의 history에서 epoch별 train loss와 tune F1을 확인합니다.
3. 오분류 사례의 정답·오탐·누락을 원문과 대조합니다. 자동 분석의 추정을 사실로 바꾸어 말하지 않습니다.
4. 로컬 API의 `/docs`에서 공개 문헌을 등록하고 AI 예측과 검토 결과가 분리되는지 확인합니다.
5. 자기 설명 범위와 AI 코딩 도구의 구현 지원을 구분하고, 이해하지 못한 수식이나 완료하지 않은 작업을 경험으로 주장하지 않습니다.

실제 개발 시각·실패 로그·모든 비교 조건을 보존합니다. 기존 개별연구의 이론 학습과 이번 구현을 연결하되 기간을 소급하지 않습니다.
